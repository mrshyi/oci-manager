# 本地开发与验证指南（当前 PC / Windows）

本指南回答的是「在**这台开发机**上怎么改代码、怎么验证」，与 `docs/VPS-部署与验收指南.md`（上线到服务器）是两回事。
本文基于本机实测结论撰写。

---

## 1. 环境现状（本机已确认）

| 项 | 值 | 备注 |
|---|---|---|
| Go 工具链 | `_tools/go/bin/go`，go1.27.3 | 仓库自带，**不用系统装 Go** |
| `GOOS` / `GOARCH` | `windows` / `amd64` | 原生，测试能直接跑；若被设成 `linux` 见 §6 |
| `CGO_ENABLED` | `0` | SQLite 用纯 Go 实现（`modernc.org/sqlite`），静态编译无 CGO 依赖 |
| `GOPROXY` | 默认 `https://proxy.golang.org,direct` | 国内拉 `modernc.org/libc` 会被网关挡，**跑测试/编译前先设 `goproxy.cn`**，见 §5 |
| gcc | **无** | `go test -race` 跑不了，见 §5 |
| Node / npm | v22.22.2 / 10.9.7 | 前端开发才需要；后端不依赖 Node（前端产物已提交进 `internal/web/dist`） |

## 2. 后端：直接跑起来

```bash
cd oci-manager
./_tools/go/bin/go run ./cmd/server
```

- 默认监听 `127.0.0.1:8080`，数据写入 `./data/`（自动生成 `oci-tools.db` + `master.key`）。
- 首次启动日志：`尚未初始化，请在浏览器中打开面板完成首次设置`。
- 浏览器开 `http://127.0.0.1:8080` 完成管理员 + TOTP 设置。

想让后端直接读磁盘上的前端产物（改前端不用重编 Go）：

```bash
OCICORE_STATIC_DIR=./internal/web/dist ./_tools/go/bin/go run ./cmd/server
```

> Windows 的 PowerShell 里环境变量写法不同：`$env:OCICORE_STATIC_DIR=".\internal\web\dist"; .\_tools\go\bin\go run .\cmd\server`。下面统一用 Git Bash 语法。

---

## 3. 前端：独立开发

```bash
cd web
npm install
npm run dev        # 开发服务器 5173，/api 自动代理到 127.0.0.1:8080
```

改完前端要编进二进制时：

```bash
cd web
npm run build      # vue-tsc 类型检查 + vite build，输出到 internal/web/dist
```

> Vite 的 `outDir` 指向 `internal/web/dist`，被 `go:embed` 打进二进制。**那个目录不存在 Go 会直接编译失败**——仓库里已经提交了产物，正常不用自己 build。

类型检查（不改产物）：

```bash
cd web && npm run typecheck
```

## 4. 构建本机单二进制（Windows）

```bash
./_tools/go/bin/go build -ldflags "-s -w -X main.version=dev" -o _dist/ocicore.exe ./cmd/server
```

`CGO_ENABLED=0` 是默认值，这里不需要写。产物约 13–14 MB。

## 5. 验证（核心）

### 5.1 全量后端测试

```bash
# 国内网络先设镜像，否则首次可能卡在拉 modernc.org/libc
export GOPROXY=https://goproxy.cn,direct

./_tools/go/bin/go test ./...
```

本机实测：`go build ./...`、`go vet ./...`、`go test ./...` 全绿（17 个包）。

### 5.2 只跑本项目改动相关的包（更快的反馈回路）

P1-0 调度器重构、P1-1 `ops_tasks` 与状态机，对应的测试集中在四个包：

```bash
export GOPROXY=https://goproxy.cn,direct
./_tools/go/bin/go test ./internal/tasksched/... ./internal/store/... ./internal/httpapi/... ./internal/huntsvc/...
```

关键测试（改这些包时必看）：

| 包 | 测试 | 防的是什么 |
|---|---|---|
| `tasksched` | `TestTickDoesNotRunSameTaskTwice`、`TestBackoffStaircase`、`TestClaimSetConcurrentAcquireOnlyOneWins`（64 goroutine） | 同一任务被两轮 tick 并发执行；退避阶梯不连乘；并发闸门 |
| `store` | `TestOpsStateMachineMatrix`（36 组合）、`TestDueOpsTasksExcludesPaused`、`TestResetRunningOpsTasks`、`TestUnixToTimeRoundTripsZero` | 状态机白名单；paused 不被捞；重启恢复；时间零值对称 |
| `httpapi` | `TestListOpsTasks`、`TestOpsTaskActionRejectsIllegal`（409）、`TestDeleteOpsTaskOnlyTerminal` | 接口鉴权、非法转换 409、删除只终态 |
| `huntsvc` | `TestHuntCreatesExactlyOneInstanceDespiteRetries` | 重试只产生 1 台实例（假 OCI 端到端） |

### 5.3 前端类型检查

```bash
cd web && npm run typecheck
```

### 5.4 本地冒烟（端到端的最小验证）

启动服务后：

```bash
# 健康检查（公开端点）
curl -s http://127.0.0.1:8080/api/status | head -c 300; echo

# 运维任务接口未登录必须 401（P1-1 关键点）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/tasks
# 期望：401

# 库里确有 ops_tasks 表与两索引
sqlite3 ./data/oci-tools.db ".schema ops_tasks"
sqlite3 ./data/oci-tools.db "SELECT name FROM sqlite_master WHERE type='index' AND tbl_name='ops_tasks';"
```

> 没有 `sqlite3` 客户端时，`strings ./data/oci-tools.db | grep -i idx_ops` 能粗略确认索引名存在。

## 6. 两个本机特有的坑

### 6.1 `go test -race` 跑不了（无 gcc）

竞态检测需要 cgo，本机没有 gcc，会报 `cgo: C compiler "gcc" not found`。
并发正确性目前靠两层保证，不依赖 `-race`：

- `ClaimSet` 的互斥由 64 goroutine 并发抢占测试覆盖；
- `Scheduler` 的 WaitGroup 与 claim 释放顺序由「跑完再捞一次」的测试覆盖。

**有 gcc 的环境**（CI 或装了 MinGW/TDM-GCC 的机器）建议补跑一次：

```bash
CC=gcc ./_tools/go/bin/go test -race ./internal/tasksched/...
```

### 6.2 若 `GOOS` 被设成了 `linux`

有人为了「直接产出部署二进制」把 `go env -w GOOS=linux`。这会让 `go test ./...` 也交叉编译成 ELF，
测试二进制在 Windows 上**根本跑不起来**。本机当前是 `windows`，正常没问题；
但若踩到，临时覆盖即可：

```bash
GOOS=windows GOARCH=amd64 ./_tools/go/bin/go test ./...
```

## 7. 提交前自检清单

```bash
export GOPROXY=https://goproxy.cn,direct
./_tools/go/bin/go build ./...     # 全量编译
./_tools/go/bin/go vet ./...       # 静态检查
./_tools/go/bin/go test ./...      # 全量测试
cd web && npm run typecheck        # 前端类型
```

推送后 GitHub Actions 会跑同样的检查，外加 `gofmt` 与一次前端试构建。
